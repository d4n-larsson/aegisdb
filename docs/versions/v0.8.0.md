# AegisDB v0.8.0 — reasoning over memory, not just retrieving it 🧩

**A memory can now carry a machine-readable claim, and the server can draw
conclusions from it.** A record's `data` is prose you can rank; an optional
`fact` is a `{subject, predicate, object}` triple you can *ask*. Given a
declared vocabulary, a background job closes the transitive, symmetric and
`inverse_of` rules over those triples, links every conclusion to its premises,
and reports the contradictions it finds without resolving any of them.

This is Horizon 5 in full — a queryable relationship graph, typed facts, a
predicate registry, deterministic inference and truth maintenance, and the
neuro-symbolic seam that lets a model write and read symbols without ever
sitting inside the inference loop.

Minor bump. Everything here is **off by default** and additive on the wire; the
one behavioural change to an existing operation is a paging fix. There is no
migration and no new file in the data directory — but the record codec gains
two versions, which matters if you replicate. Details under *Operator notes*.

## What changed

### A relationship graph you can question (5.1)

`kind` on an edge was inert: `traverse` followed every outgoing neighbour and
there was no reverse adjacency, so "show me the supersession chain" was a blind
walk plus client-side filtering and "what points at this?" was a full scan.

```json
{ "operation": "traverse", "id": 42, "depth": 3,
  "kinds": ["supersedes"], "direction": "in" }
```

`kinds` (union, up to 16) filters the walk rather than the result, so an
excluded edge is never followed and its subtree is never read. `direction` takes
`out` (default), `in` or `both`. Every returned record carries a `traversal`
object — `depth`, `via_id`, `via_kind`, `via_direction` — so a result reads as a
path instead of a set whose shape has to be inferred.

Only the reverse direction needs an index; a record is already its own forward
adjacency list. A traversal visits at most 8192 records and reports `capped`
when it stops early — outdegree is capped per record at 4096, indegree at
nothing, so a backward walk from a heavily-referenced record was the unbounded
case.

### Typed facts and a vocabulary to write them in (5.2)

```json
{ "operation": "insert", "type": "semantic",
  "data": "The recall hook defaults to embedding_mode=none.",
  "fact": { "s": 42, "p": "defaults_to", "o": "none" } }
```

Neither half is derived from the other: the prose stays what a human or a model
reads, the triple is what a rule fires on. Entities are records, so a fact about
"the recall hook" names the id of a record describing it.

`search` and `count` take a `pattern` binding any non-empty subset of the three
positions — `{"s": 42, "p": "defaults_to"}` asks what 42 defaults to,
`{"p": "part_of", "o": {"id": 99}}` asks what is inside 99. An all-wildcard
pattern is refused rather than served: it is a scan of every fact wearing a
filter's clothes. Bulk `delete` refuses a pattern too, rather than ignoring it —
deleting by pattern would be a new destructive capability.

`--predicate-registry <file>` declares the vocabulary, and with one configured a
fact naming an undeclared predicate, or the wrong object kind for it, is refused
at insert. The registry is validated at **startup**, and a problem is a startup
failure naming the predicate — not a fallback to accepting everything, which
would be the opposite of what configuring a registry asks for. The new
`predicates` operation reports the vocabulary over the wire, so a client on
another machine can learn what it is allowed to assert.

A fact is **immutable**: `update` changes tags and payload and leaves the triple
alone, because changing what a record asserts is a supersession rather than an
edit.

### Inference, and knowing why you believe something (5.3)

`--inference` (off by default) materializes the transitive, symmetric and
`inverse_of` closures on the maintenance tick, per namespace, never on a
replica. Each conclusion is an ordinary semantic record carrying the concluded
fact and `derived_from` edges to every premise, so an inference is
provenance-linked by construction:

```json
"explain": { "derivation": { "depth": 2, "routes": [
  { "rule": "transitive", "premises": [ {"id": 12, "live": true},
                                        {"id": 19, "live": true} ] } ] } }
```

Support is **disjunctive** — a conclusion carries the *set* of independent
routes that justify it, because retraction has to ask whether *any* justification
survives, and a flat premise list cannot answer that. Retraction withdraws a
conclusion when every route has lost a premise, follows `supersedes` so a merged
premise is not mistaken for a lost one, and is reconstructed by recovery rather
than persisted — which turns "the queue was flushed" into the stronger invariant
*no live derived record has a dead premise*, checkable on every restart.

`subsume: true` on a `search`/`count` `pattern` broadens a bound subject through
the `is_a` taxonomy, so a fact about a member answers a question about its
category. It is off by default because it changes what a pattern *means*.

Contradictions are **found and never settled**. Two live values for a
`cardinality: one` predicate, or two predicates declared `mutex_with` each
other, produce a `conflicts_with` edge both ways and a `stats` gauge; the new
`conflicts` operation lists the pairs. Choosing a winner needs to know which is
newer, which source is better, or what the world is like — none of which the
server knows. What it guarantees is that the contradiction is found, with no
model call.

### The neuro-symbolic seam (5.4)

The model is the *interface* to the symbolic store, never inside its loop.
Three jobs, all in the Claude Code integration:

- **Parse** — prose to candidate triples, prompted against the registry as a
  controlled vocabulary. A rejected triple is dropped and counted, never coerced
  onto the nearest declared predicate; the prose stays in `data` and stays
  searchable, so an extraction yielding no triple degrades to exactly what the
  previous release did.
- **Ground** — resolve a mention to an existing entity id by hybrid retrieval
  before minting a new one, deliberately biased toward fragmentation: conflating
  two entities writes facts about the wrong thing and inference then derives more
  of them, while splitting one entity in two only loses inferences and
  `consolidate` can merge them afterwards. One error is recoverable; the other
  is not.
- **Adjudicate** — when the rules flag a contradiction they cannot settle, the
  model sees that one pair and answers A, B or **neither**. Neither is
  first-class and is the default, so an unreachable backend or an unparseable
  reply abstains. A verdict is written as a supersession, never an edit. Off by
  default and capped per run — this is the one place a model error becomes
  durable state.

The read path gained `ask`: a question becomes a `pattern`, and a derivation
that already exists is verbalized back into English. The model *reads* the
proof; it never produces it.

### Clients, and one fix worth reading

- **`aegisdb`** — a dependency-free Python client SDK, on PyPI.
- **`aegisdb-langgraph`** — AegisDB as a LangGraph store, on PyPI.
- **`aegisdb-mcp`** now names the server's predicate vocabulary in the
  `memory_search` description, so the model knows what it may ask about.
- The Prometheus exporter reports distillation backlog (opt-in: it is a filtered
  scan rather than a counter read).
- **`search` with `offset` now pages correctly.** The unranked comparator did
  not break ties on id, so every page ran a different selection over the same
  tied candidates — skipping records and repeating others, in eight of twelve
  trials on twelve records paged two at a time. `created` is milliseconds, so
  ties are the common case rather than an edge one. The order is now total and
  pages compose into the same sequence a single large `top_k` returns.

## Operator notes

- **Nothing new is on.** `--predicate-registry` unset accepts any predicate;
  `--inference` unset derives nothing. A deployment that ignores this release
  behaves exactly as v0.7.0 did, apart from the paging fix.
- **The two flags are a pair.** `--inference` without a registry derives nothing
  either: the closures draw what the registry *declares* `transitive`,
  `symmetric` or `inverse_of`, and with no registry no predicate is declared
  anything. `subsume` likewise needs `--inference`, and reports `NOT_READY`
  without it rather than quietly reaching direct members only.
- **The record codec gains v3 (a fact) and v5 (a derivation).** A record is
  encoded with the *lowest* version that can represent it, so a fact-less record
  is still v2 byte-for-byte and an existing log is unchanged on disk. A format
  change nobody can downgrade past is confined to deployments that opted in.
  Version 4 is deliberately skipped and refused on decode.
- **Replication now negotiates a codec version.** Previously a primary writing a
  newer format streamed frames an older replica could only reject frame by
  frame, with no way to say why. The handshake carries `codec_version` and the
  primary withholds a frame the replica cannot decode, naming the offset and
  both versions. **Upgrade replicas before the primary**, or the primary will
  correctly refuse to ship them facts.
- **Two new in-RAM indexes**, both derived, neither checkpointed, both rebuilt
  by recovery and both counted toward `--max-index-bytes`: the reverse edge
  index (`--no-edge-index` opts out, and makes a reverse `traverse`
  `NOT_READY`) and the fact indexes (`--no-fact-index` opts out, and makes
  `pattern` `NOT_READY`; the fact is still *stored*, only the lookups go away).
  `stats` reports `edges`/`edge_kinds`/`edge_bytes` and
  `facts`/`fact_predicates`/`registered_predicates`/`fact_bytes`.
- **Edge index RAM tracks fan-in**, not edge count: measured ~121 B/edge at one
  source per target (the provenance shape), ~17 B/edge at a thousand.
- **`--inference` grows the log, not RAM** — conclusions are records. Bound a
  pass with `--inference-max-derived`, `--inference-max-candidates` (which is
  what actually bounds a tick), `--inference-max-depth`,
  `--inference-max-subsume` and `--inference-confidence-floor`;
  `--inference-interval-sec` paces it.
- **`conflicts` answers rather than erroring when inference is off**, returning
  an empty list, so an adjudication loop does not need to know whether the
  feature is on.

## Measured

- **`make eval-multihop`: symbolic 100% against retrieval 0% at recall@5**, on
  questions whose answers live in no single record. The gate bounds retrieval as
  well as the symbolic path, which is what caught a first dataset that answered
  half its own questions by word overlap.
- **`make eval-extraction`, one run of `--extractor claude-code`:**
  in-vocabulary **100%** (22 proposed, 0 rejected), conflation **0**,
  fragmentation 2 entities → 4 ids, gold recall 92%. A spot reading of a
  non-deterministic model rather than a gate — but the first evidence for the
  claim the seam rests on: prompted against a registry, a model does not invent
  predicates. The gate itself runs the deterministic `fake` backend, whose
  in-vocabulary rate is a property of the dataset rather than a model score, and
  the harness says so on every fake run.
- **A worked corpus ships.** `predicates.example.json` is a ten-predicate
  starter vocabulary; `tools/facts/` carries two hand-written corpora about this
  project that load through it (`make seed-facts`, `make seed-surface`). Loaded
  together, 206 asserted facts become 367, with 161 derived and every `contains`
  fact among them derived rather than written.

## Known limitations

- **The registry is a contract, and where its line sits is empirical.** The
  extraction eval reports `unstatable` — triples a careful reader would write
  and the vocabulary cannot express — so "grow the registry" stays a decision
  with a number behind it. A registry that grows to fit every transcript has
  stopped being a contract.
- **Grounding drifts as the corpus grows.** A threshold tuned on a small store
  may conflate on a large one, where more entities means more near-misses. The
  minting rate is the leading indicator and is reported.
- **The earliest facts are the most fragmented.** The first transcript on an
  empty store mints everything, having nothing to resolve against.
  `consolidate` can merge entity records afterwards, but nothing schedules it.
- **No literal normalization.** "five seconds" and "5s" are one literal to a
  reader and two to the index.
- **`pattern` is a filter, not a query language** — no variables, no
  disjunction, no joins — and inference is three closures rather than a Datalog
  engine. Both are deliberate and neither is planned to grow.
- **Consolidation lineage is not reachable by `traverse`.** A merge tombstones
  the records it absorbs and deleting a record drops the edges pointing at it,
  so the lineage is visible only in the survivor's `relationships` array.
