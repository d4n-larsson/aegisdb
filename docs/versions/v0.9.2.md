# AegisDB v0.9.2 — the setup now has to prove it works 🧪

**Integration-only.** The server, the wire protocol and the on-disk format are
v0.9.0's; the image is republished at this tag carrying the same code.

This one came out of installing AegisDB into a throwaway project and then
actually using it. The install succeeded, `aegisdb-doctor` went green, and the
integration was **dead**: the memory server never started, the recall hook
injected nothing, and nothing anywhere said so.

Everything the scaffolder writes — the memory server and both hooks — runs
through one launcher, and that launcher's failure mode is silence. A hook that
cannot start prints nothing and Claude Code reports nothing; a memory server
that cannot start is reported as simply absent, no tools and no reason.

## The doctor proves the chain instead of inspecting it

Two checks used to be taken on trust. Both are now exercised:

```text
✓ mcp entry   `memory` registered in .mcp.json
✓ mcp runs    the memory server completes a handshake
✓ hooks       recall + capture wired in .claude/settings.json
✓ hook runs   the recall hook runs
✓ round trip  saved record 41, recalled it through the hook, removed it
```

- **`round trip` goes through your hook.** It used to write a memory and find it
  with the library. A hook is contracted to exit 0 whatever happens — memory is
  best-effort and must never block a turn — so its exit code only ever showed
  that the command *started*. The probe record now carries a unique token and
  the actual recall hook has to hand that token back. One unusual word, planted
  in the memory and repeated in the prompt, so the match does not depend on
  stemming, on embeddings, or on what else is in the store. The record is
  deleted either way.
- **`mcp runs` starts the registered server** and completes one `initialize`
  handshake — proof that the launcher execs, the package resolves, the SDK
  imports, and the process speaks the protocol Claude Code will speak to it.

On a project broken the way that walkthrough was, the report now reads:

```text
✓ hooks       recall + capture wired in .claude/settings.json
✓ hook runs   the recall hook runs
✗ round trip  the hook did not recall a memory written seconds ago — it exits
              cleanly and injects nothing, which is what a session sees
```

Named, started, useless: three separate lines, which is the whole diagnosis.

## `aegisdb-init` proves the launcher before writing it

It now asks the memory server command for one handshake before scaffolding
anything. If the console scripts cannot answer, the project is wired through
`python -m aegis_mcp.server` and `python -m aegis_mcp.hooks` instead — the same
package with one less shim — and it says why. `--launcher script|module` forces
either form.

`python -m aegis_mcp.hooks recall|capture` is a new, supported way to run the
hooks, and is what makes that fallback reachable.

## Fixed: two ways a second hook could appear

Both would have made a project recall twice into a single turn and capture the
same session twice.

- **`aegisdb-init` matched only its own command**, so it would add a hook beside
  a path-run one that already worked. It now recognises every form, updates the
  ones it wrote, and **leaves a wiring it did not write alone**.
- **The doctor did not recognise the new `python -m` hooks**, and called a
  project `aegisdb-init` had just scaffolded "not wired" — with advice that
  would have added the duplicate. Both sides now read one shared list.

## Operator notes

- **Nothing to migrate, and nothing to redo.** An existing project keeps the
  wiring it has; re-running `aegisdb-init` updates the hooks it wrote rather
  than adding to them.
- **The doctor spawns two processes now** — your memory server (killed as soon
  as it answers) and your recall hook. `--no-write` still skips the round trip,
  which is the only part that touches the store.
- **A first run can be slow.** Both probes may trigger a cold `uvx` fetch; the
  timeouts allow for it and report a timeout as a warning, not a failure.
- **Known, not fixed here:** with `embedding_mode: none` — the default — recall
  is exact-token keyword matching. *"how do I deploy this project?"* does not
  match *"widgetco deploys with make ship"*, on the plural alone. If recall feels
  empty, that is the likeliest reason: set `embedding_mode` to `voyage` or
  `local`.
