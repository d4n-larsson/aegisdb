# AegisDB v0.9.4 — the capture hook stores something, and stops 🧯

**Integration-only.** The server, the wire protocol and the on-disk format are
v0.9.0's; the image is republished at this tag carrying the same code. Every
change here is in `integrations/claude-code`.

Two fixes in the SessionEnd capture hook. The first is why your store may be
empty. The second is what the first makes necessary, and they ship together on
purpose — the second has never been needed by a released version, because the
first has never been in one.

## 1. Capture had never stored a memory

Not "sometimes", not "since some change" — never, in this repo, and nowhere else
it was wired the same way.

Claude Code cancels a SessionEnd hook that has not finished, measured at ~1.5s
(2.1.243, `SessionEnd hook [...] failed: Hook cancelled`), by killing the hook's
process group. Capture cannot win that race and was never close to it:

| | |
|---|---|
| `embedding_mode: local` | reloads sentence-transformers in a fresh process — **~4.6s** |
| `extract_mode` | shells out to a model with a 24000-char blob — **~38.5s** |

The failure was invisible because the hook is *designed* to be quiet: it always
exits 0 and prints to a stderr nobody reads, so "cancelled at 1.5s" and "nothing
in this session was salient" produce exactly the same silence.

**The fix is `fork` + `setsid`.** The hook returns 0 immediately and the capture
runs on in a session of its own, so the cancellation kills a process group the
worker is no longer in. Verified end to end: hook returns in 0.06s, worker alive
45s later, `stored 12 mem(s)`.

## 2. A capture must not capture itself

`setsid` is the right fix for the cancellation, and it removes the only thing
that was accidentally bounding a loop nobody had noticed:

```text
session ends → capture hook runs → extract_mode: claude-code shells out to
`claude -p` → that is a session → it ends → fires the same SessionEnd hook → …
```

Each generation makes roughly nine calls, depending on configuration — facts,
triples, supersede judgments — so the tree is 9 → 81 → 729, and with the worker
detached from the hook's process group nothing reaps it. The end state is a
machine out of processes.

**Two independent stops**, either of which ends the recursion alone:

- The capture marks its environment `AEGIS_CAPTURE_ACTIVE=1`, inherited by
  everything it spawns, and **both** hooks return at once when they see it —
  before the config load, before the fork.
- The `claude` it starts runs with `--safe-mode`, so it loads no hooks at all.
  The flag is probed once against the CLI on PATH rather than assumed, because a
  version predating it rejects the whole invocation; unprobeable reads as
  unsupported and the environment mark carries alone.

Both are in one module (`aegis_mcp/claude_cli.py`) that owns the only `claude`
invocation in the package, so there is one thing to audit rather than two to
keep in sync. The guard covers recall as well: a session a capture started to
ask a model a question is not a session whose prompt wants memories injected.

## Operator notes

- **Nothing to migrate.** No server change, no on-disk change, no re-index.
- **The capture hook's exit code now means the capture *started*.** It returns
  before the work is done. Set `AEGIS_CAPTURE_DETACH=0` to run it inline if you
  need the exit code to mean it finished — which is what the contract tests
  asserting on stored records do.
- **Point `AEGIS_CAPTURE_LOG` at a file.** The worker outlives the pipes Claude
  Code was reading, so without it a detached capture's diagnostics — `stored N
  mem(s)`, triple counts, the reasons a feature stayed inert — go to
  `/dev/null`. This repo points it at a gitignored `.aegisdb/local/capture.log`.
- **The transcript must outlive the hook**, since the worker reads it afterwards.
  Claude Code keeps its transcripts, so this only bites a caller that cleans up
  eagerly — a test, for instance.
- **Do not export `AEGIS_CAPTURE_ACTIVE` yourself.** It is set by capture, for
  capture. A `1` in your own shell turns off capture *and* recall for everything
  started from it.
- **Recall is untouched.** It must answer inline — its whole output is the
  context it injects — and at ~51ms with `embedding_mode: none` it has no
  shutdown race to lose.
