# AegisDB v0.9.3 — recall that does not need your exact words 🔤

**Integration-only.** The server, the wire protocol and the on-disk format are
v0.9.0's; the image is republished at this tag carrying the same code.

One fix, for the thing most likely to have made a default install feel like it
remembers nothing.

## The problem

With `embedding_mode: none` — what a new project gets unless it is told
otherwise — the keyword index is the only content-based retrieval there is, and
it matches whole tokens. Recall therefore fired only when a prompt happened to
reuse a memory's exact words:

```text
"how do I deploy this project?"   →   missed   "widgetco deploys with make ship"
```

One letter of difference. If recall has felt empty and you have not set a real
embedding provider, this is the likeliest reason.

**And the reverse, which is worse.** The index has no stopword list, so *any*
question containing "the" matched *any* memory containing "the". On a small
corpus IDF has nothing to push against, so recall injected an unrelated memory
into the turn — scored, and looking authoritative:

```text
"what is the kubernetes ingress annotation?"   →   "the proxy is guarded by an API token per tenant"
```

## The fix

Both live in the query the client sends on the keyword-only path: function words
are dropped, and light morphological variants are added. Measured against a real
server on a four-memory corpus:

| | questions that found the right memory | unrelated memories injected |
|---|---|---|
| before | 5 of 6 | 6, across 3 off-topic questions |
| after | **6 of 6** | **0** |

This is query expansion, deliberately **not** a stemmer. A stemmer normalises
both sides of a match, which needs the index to agree — and it would blunt the
exact-identifier matching that makes the keyword path worth having. Expanding
the query leaves the index untouched: the server's keyword search is a
disjunction scored by IDF, so a variant that matches nothing costs nothing.

## What still will not work

```text
"where does the deployment happen?"   →   still misses   "deploys"
```

Derivational morphology is a stemmer's job, and the trade above is why there is
not one. **Set `embedding_mode` to `voyage` or `local` if recall matters**: a
question reaching a memory that says the same thing in different words is what
embeddings are for, and no amount of keyword cleverness substitutes.

## Operator notes

- **Nothing to migrate, and nothing to re-index.** The change is in what the
  client sends, not in what the server stores.
- **Only the keyword-only path changes.** With embeddings on, the query is sent
  verbatim as before — the semantic side already spans the morphology, and extra
  terms would only tilt the fusion the server does between the two.
- **Identifiers are untouched and never dropped**, however short:
  `--tenant-max-records`, `hnsw.c:214`, `0x7f`, `v0.9.2`. Exact matching on those
  is what the keyword path is for, and it is unchanged.
- **A question made entirely of function words is sent as asked**, since an
  empty query is not a query.
- `aegisdb-doctor`'s note for `embedding_mode: none` now describes this
  accurately: recall matches keywords, not meaning.
